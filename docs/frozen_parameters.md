# Frozen (Seal-Time) Parameters — 10 of 11 set, 1 deferred by decision

Every parameter below **must** be frozen and hashed before sealing
(`EXPERIMENT_ARCHITECTURE_FINAL.md`, Part H step 3). **Rows 1 (ADR 0026), 2 and 7 (ADR 0025), 3 (ADR 0027), 4, 6 and 10 (ADR 0022), 8 (ADR 0016)
and 11 (ADR 0019) are set. Row 5 is **deferred by decision** (ADR 0028) and is never to be
filled. Row 9 alone is still open, and it is read off the measurement box at seal time rather
than chosen.** The equivalence
margin and the G-3 latency smoke threshold **must** be fixed from external engineering need
**before any timing measurement** (Part H step 2; Part G, G-3; Part J.2 item 9) — the G-3
threshold first, the equivalence margin separately and after it, both before any confirmatory
timing result. Fixing each value is a decision: record an ADR (`adr/`) and fill in the value and
justification here.

**Machine-readable tokens.** Each scalar row below carries its value as an explicit
`name = value` token, the same idiom rows 4/6/8/10/11 use for `H(Λ)`/`H(Γ)`/`H(R)`.
`src/harness/frozen_parameters.py` is the single reader of every one of them, so no second
copy of a frozen value exists in code, and **any comparison against a row that is not set
fails closed** rather than defaulting.

| 1 | Equivalence margin for the "lightweight" claim | **SET (ADR 0026).** `equivalence_margin_ms = 20`. **Estimand:** `median(B3) − median(B0)` over the measured segment, **warm path**. **Decision rule:** the claim stands iff the **upper bound of the 95% bootstrap confidence interval** on that difference is `< 20 ms`; a point estimate below the margin with a CI upper bound above it does **not** support it. **Sampling:** ≥ 200 end-to-end repetitions per configuration across ≥ 3 independent batches, cold and warm reported separately, condition order randomised or Latin-square counterbalanced within each batch, warm-up discarded. **Measured segment:** `presentation + boundary_verification`, each bracketing exactly one call — `arm.present(...)` and `arm.decide(...)` respectively — with instrument bookkeeping, the `MediationEvent`, **every effect-ledger append**, the tool's own execution, `provision` and `delegate` all excluded by name (ADR 0026 §"The measured segment"). **One cell is excluded from every per-arm mean, by name:** on `gt-f1-chain-tamper` the **exchange arms perform a failed AS round trip and receive no token**, while the capability arms do purely local work. Pooling that cell with benign cells would average a network refusal together with local cryptography. **Refusal-path latency is reported as its own series** and is never folded into a benign per-arm mean nor into this row's estimand. This carries into the G-3/RQ4 analysis plan (§J.3 item 12). | ADR 0026: 20 ms is 1% of `T_full` (row 7) and is precisely the per-step operating point published runtime agent-guard work already treats as deployable, so "lightweight" acquires an operational definition rather than remaining an adjective. Deliberately **not** equal to row 2: a gate threshold wants headroom, an equivalence margin encodes what the field tolerates, and they answer different questions. The segment is pinned here because the pre-existing seam bracketed `decide` alone and omitted `B3`'s principal per-invocation cost — an omission that ran **toward** this work's own hypothesis and is fixed before any measurement, not after. |

| 3 | Freshness window `Δ` | **SET (ADR 0027).** `delta_seconds = 60`, and the **same** `Δ` governs all three consumers: the `jti` replay cache TTL (entries live exactly `Δ`; eviction by age, never by an independent timer), the DPoP proof `iat` acceptance window (fresh iff `|now − iat| ≤ Δ`), and INV freshness at the boundary (identical rule, identical `Δ`). Two conditions travel with it: every consumer takes `now` as an **injected** parameter and none reads a wall clock, and over-window fixtures **advance the injected instant** — real waiting is forbidden and a test asserts no replay path sleeps. Replay-cache budget: `replay_cache_capacity = 65536` (2^16), **fail-closed on overflow** — an insertion that cannot be recorded is a **denial**, never an admission and never a silent eviction of an unexpired entry. | ADR 0027: RFC 7519 §4.1.4/§4.1.5 allow *some small leeway, usually no more than a few minutes* for clock skew and 60 s sits at the conservative end; RFC 9449 leaves the DPoP window to the server, so no specification fixes it for us. `Δ` is an **apparatus constant chosen for comparability**, not a security recommendation. One window because **G-14** attaches the same cache to `B2-DPoP` and `B3` — differing windows would make any difference it observed an artifact of the apparatus in the very gate whose purpose is attribution. 2^16 is three orders of magnitude above the working set, so the budget exists to make the overflow path **reachable and testable**, not to be approached; fail-closed rather than LRU because evicting an unexpired entry would let an attacker replay by first flooding the cache. Availability is deliberately sacrificed to integrity, as apparatus, not advice. |
